# Rails 8 API Authentication v1.0.0 Direct-Stable Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Convert the release-hardening track to a direct first stable `v1.0.0` release while preserving frozen baselines, logical commit separation, fail-closed verification, and truthful runtime provenance.

**Architecture:** Keep application/authentication behavior and frozen PostgreSQL/SQLite artifacts unchanged. Rebuild the release branch as `release/v1.0.0`, retain four logical implementation commits, then add one evidence-only acceptance commit after the new exact candidate is fully qualified.

**Tech Stack:** Git, GitHub Actions, Bash, Ruby, Docker Buildx, Beam.cloud, Hugging Face Spaces.

**Spec:** `docs/superpowers/specs/2026-09-08-v1.0.0-release-hardening-design.md`

## Global constraints

- `main` base remains `dbb33261ca274064f93f58cf8bdfe24092d22452` until merge.
- PostgreSQL baseline remains `6897c773ec1321401e52c21c63870a72d01ca349`.
- SQLite baseline remains `1d842b18c1d1b07c027cbb7d49c19a52d16f98bc`.
- Baseline branches/tags are never rewritten or moved.
- No public prerelease tag is created.
- First semantic-versioned public tag is `v1.0.0`.
- Release state is fail closed: `NOT RUN`, `BLOCKED`, `FAIL`, `PASS`.
- No secret values are committed or printed.
- Do not squash unrelated logical commits.

### Task 10: Merge and publish stable v1.0.0

Immediately before merge:

```bash
bash scripts/release/verify_ghcr.sh
```

Require PR checks and repository controls to be PASS. Then merge the reviewed PR and verify merged `main`.

Create the immutable annotated stable tag on the accepted implementation SHA recorded in the evidence document:

```bash
git tag -a v1.0.0 "$ACCEPTED_IMPLEMENTATION_SHA" -m "Rails 8 API Authentication v1.0.0"
git push origin v1.0.0
```

Publish a non-prerelease GitHub release. Then run:

```bash
git ls-remote origin refs/tags/v1.0.0
bash scripts/release/verify_ghcr.sh
```

Perform an additional deployment health check. Any source correction after publication requires a subsequent semantic version; never move `v1.0.0`.

## Self-review result

- Direct stable semantics replace the previous RC-to-stable promotion path everywhere in the release model.
- Frozen baseline and GHCR verification semantics are unchanged.
- Logical commit separation is retained.
- Exact-candidate evidence is re-established after rewrite; no old SHA is silently reused as the final stable candidate.
- Acceptance evidence remains evidence-only and fail closed.
